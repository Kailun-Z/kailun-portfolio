案例 01 · 数据产品 · 2026.07 – 2026.09

联合国秘书长报告数据库（UNSGR）

把 1994–2025 年 2,933 份秘书长报告，连同授权它们的决议、它们要履行的报告义务、以及报告之后安理会的回应，做成一个每个值都能回溯到原句的关系数据库，并以查询网站、CSV 和只读 API 发布。

问题

安理会每次行动前都先读秘书长报告，但"谁要求的、何时该交、交了之后怎样"从来没被记录成数据

国际关系学者要回答的问题是：安理会对秘书长报告有没有回应、回应到什么程度。做不了，有三个原因。

  1. 一
    义务不写在报告封面上。决议是 15 国逐句谈出来的固定格式，好表格化；报告是各特派团自己写、格式没人规定。一份报告是哪条决议要求的、该什么时候交，只能从外部文书反推。
  2. 二
    读不过来。30 年 2,933 份报告和相关决议散在 6 个官方来源，部分年份缺失，此前只能逐份人工阅读、无法系统比较。
  3. 三
    "回应程度"需要一套指标。不是简单的有或没有：要有基线，才能说一次"没回应"是结果还是缺失值。
方案

先把研究问题翻成指标，再让规则、模型、人各做自己最值钱的那一步

1 · 定义问题

把"授权 — 报告 — 回应"定义成三类指标、21 个核心变量，逐条和合作者确认口径。回应程度按报告后 90 天内安理会的最高产出分五档（决议 / 主席声明 / 新闻声明 / 仅开会 / 无），再和报告在授权周期中位置对应的制度默认值比较，偏离默认值才算回应多或少。

2 · 分工：规则先行，模型交叉预标，人工只裁分歧

合作方是非技术背景的领域专家，没有精力做全字段人工标注；直接用 AI 的结果又不可复现、过不了同行评审。所以：确定性规则只从报告开头段抽报告级字段，版本化、可回归；两家厂商的大模型只做"提议者和第二读者"，输出验证后才入库；人工只裁决模型之间有分歧的地方。先用 5 份报告双人试标定规则，沉淀 12 条编码规则，验收阈值事先锁定。

3 · 管线与数据模型

年度报告表 + UN 数字图书馆列全集 → 决议/主席声明/新闻声明/表决记录同一解析器 → 规则层抽报告级字段 → 从决议操作段抽 927 条报告义务 → 2,521 条链接把报告匹配到义务 → 模型提议 + 验证入库 → 网站 + 只读 API + Dataverse 发布

数据库分三层 schema：观察到的（core）/ 外部导入（external）/ 派生研究（research），research 层由脚本从 core 重建；主键用自然键（UN 文号、ISO 码、特派团缩写）。每个抽取字段带证据三件套：原句、位置、方法。空值分三类——来源没说、规则没够到、规则拒绝了位置不对的线索——都不等于"事实不存在"。

规则冻结、密封集只打一次分、数字公开后不改

项目结果怎么验的
报告级字段精确率0.971 – 1.000密封测试集 44 份报告；金标准每字段 33–43 条，模型预标后人工逐句核验
报告级字段召回率0.90 – 1.00同上；规则取 precision-first，覆盖缺口在数据质量页逐年公开
授权期末日20 / 20 一致与安理会官方授权表逐条对照
国别投票27,973 条逐票一致与会议记录（SPV）对照
模型与规则层一致率81.0% → 86.7%开发集 → 留出集；分歧归类裁决一次，把报告义务链接从 3,617 提高到 3,885
人工编码工作量约 2 周 → 约 1 天人工从全量标注变为只裁分歧
最重的全表查询分钟级 → 约 1 秒物化特征表 + 全文检索调优
首个可用版本2 天从全量抓取到可查询；此后按投刊标准收敛
我的角色

两人团队的技术方

合作方负责"问什么"：定研究问题、给领域判断、裁决分歧、写理论章节。我负责"怎么让答案可复现"：把研究问题翻成数据模型、变量和代码本；抓取与抽取管线；模型预标与验证设计；网站与 API；范围管理。论文的数据与验证章节由我主写。编码规则是两个人一起定的。

以 Claude Code 为工程搭档，三周独立交付；AWS + Docker 部署 FastAPI 与 React/TypeScript；API 密钥认证与行级安全同导出共用一个谓词。

范围管理

按投刊标准收敛，而不是随需求漂移

项目要同时过期刊评审、供合作方使用，需求持续膨胀：议题名录方案复杂度超出核心目标，1.1 版承诺了 4 项尚不存在的功能，合作方一次提出 6 项修改建议。

我定了一条取舍标准——主体是报告与上下游文书，管线必须可复现——据此叫停复杂方案，砍掉 4 项承诺转为局限说明，6 项建议按必做 / 已做 / 不必分级回复取得共识；3 个第三方数据集经许可证确认后才导入。

局限

论文里自己写明的

  • 金标准是模型预标后人工核验，不是盲标，精确率可能偏乐观；下一步做一轮盲标审计并扩大金标准。
  • 规则取 precision-first，覆盖有缺口：报告期只抽到约 60%，前序报告约 43%；计划对缺口字段加第二套规则。
  • 90 天回应窗口在并行授权的议题上偏宽松，可能把别的流程的产出算成回应；1.1 版用决议引用关系做校验。
  • 内容层只有词典规则，没有语义编码；建议与呼吁的对象属于研究层派生表，不是核心数据。
